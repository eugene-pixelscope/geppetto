# 모델 영구 삭제

모델 카드의 삭제 버튼은 모델과 연결된 작업 기록, 예약, 평가 기록을 카탈로그에서 영구 삭제한다. 확인 창에 모델 이름과 삭제 범위를 표시한다. 삭제된 모델 목록과 모델 복원 API는 제공하지 않는다.

API: `POST /api/pinocchios/{id}/delete`, 본문 `{ "name": "현재 모델 이름" }`. 삭제 이후 모델과 작업 상세 조회는 404를 반환한다. 자동 동기화로 다시 가져오지 않도록 삭제한 모델·작업의 ID만 남기며 복원할 데이터는 보관하지 않는다.

진행 중이거나 자원 반환이 확인되지 않은 작업, 활성 예약이 있으면 삭제를 거부한다. 관련 기록의 제거와 재수집 차단은 같은 SQLite 트랜잭션으로 처리한다. 외부 학습 결과 파일·MLflow 원본·데이터 원본은 삭제하지 않는다.

검증: `tests/test_model_history.py`, `tests/test_selected_import.py`, `tools/browser_model_delete.py`.

---

아래는 0.3.2의 개별 이력 API 동작 설명이다. 삭제 버튼은 0.3.3부터 모델로 옮겼다.

# 작업 이력 삭제·복원 (0.3.2)

Runs 목록과 작업 상세에서 개별 이력을 삭제할 수 있다. Runs의 이력 관리 체크박스로 여러 작업을 선택한 뒤 **선택한 이력 삭제**를 누르면 확인 창에 대상 목록이 표시된다. **삭제된 이력** 화면에서는 개별/선택 복원이 가능하다. 한 번에 최대 100개를 처리한다.

삭제는 일반 작업 목록·모델별 작업 목록·해당 목록을 사용하는 화면 통계에서 제외하는 가역적 처리다. 학습 결과 파일, 등록 모델 버전/alias, 데이터 원본, MLflow 원본 실행을 지우거나 디스크 공간을 회수하지 않는다. 원본 실행과 계보는 유지하므로 파이프라인·sweep·재개·평가 관계는 보존된다. 이러한 관계 화면이나 직접 링크로 원본을 열면 삭제된 이력 안내와 복원 버튼을 볼 수 있다. 모든 이력이 삭제된 모델은 '학습 전' 대신 '이력 삭제됨'으로 표시한다.

- 완료·실패·중단·건너뜀 상태만 삭제 가능하다. 대기·제출·실행·미확인 상태는 거부한다.
- Agent Job UID가 있는 작업은 자원 반환 확인도 필요하다.
- 여러 작업 중 하나라도 삭제 불가/존재하지 않으면 전체 요청을 취소한다.
- 읽기 전용 모드에서는 삭제·복원을 거부한다. 로그인한 관리자/사용자는 공유 워크스페이스 이력을 정리할 수 있다.
- 삭제한 사용자와 시각을 보관한다. 삭제/복원 이벤트는 별도 카탈로그 레코드로 남긴다.
- 삭제 표시는 `run_history` 레코드에 별도 저장하여 MLflow 동기화가 원본 run을 갱신해도 유지한다. 외부 원본이 실행 중으로 바뀌면 활성 작업이 숨겨지지 않도록 다시 표시한다.
- 스케줄러·리소스 추적은 원본 실행을 계속 사용한다. 삭제·복원은 원본 파일이나 Kubernetes Job에 명령을 보내지 않는다.

API: `POST /api/run-history/delete` 또는 `/restore`, JSON `{ "ids": ["RUN_ID"], "confirmation": "delete" }` (복원은 `restore`). 조회는 `/api/catalog/run?visibility=active|deleted|all`, 기본값 `active`. 직접 상세 조회는 `history_deletion` 메타데이터를 포함한다.

검증: `tests/test_run_history.py`, `tools/browser_run_history.py`. 운영 데이터에 대한 임의 정리는 수행하지 않았다.

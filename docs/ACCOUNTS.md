# 사용자 계정 (0.3.1)

웹은 아이디·비밀번호로 로그인한다. Kubernetes Agent와 프로젝트 SDK 인증은 기존 토큰을 유지한다. 공용 웹 토큰 로그인과 예전 결정적 쿠키는 폐기했으며, 기존 `GEPPETTO_TOKEN`은 관리자 권한의 자동화 API 자격증명으로만 동작한다.

## 현재 서버

- 주소: https://localhost:8092 (서버 로컬; 외부 PC에서는 SSH 포트 포워딩)
- 초기 아이디: `admin`
- 임시 비밀번호: 서버의 `local/kubernetes/secrets/admin-login.txt` (권한 0600, Git/Docker 제외)
- 첫 로그인 시 새 비밀번호 설정이 필요하다. 변경 후 임시 비밀번호 파일은 삭제해도 된다.
- 사이드바 **Users**에서 사용자/관리자 생성, 역할 변경, 비활성화, 임시 비밀번호 초기화를 할 수 있다.
- 상단 계정 이름을 누르면 본인 비밀번호를 변경할 수 있다. 로그아웃은 현재 세션을 폐기한다.

## 새 설치의 첫 관리자 설정

계정이 없는 설치는 `/state/initial-admin-key`에 0600 권한으로 최초 설정 키를 생성한다. 서버 관리자는 키를 읽어 `https://SERVER/#setup=KEY` 링크를 첫 관리자에게 전달한다. 키를 화면에 붙여 넣어도 된다. URL의 fragment는 서버로 전송되지 않고 브라우저 초기화 시 제거된다. 일반 사용자는 이 키를 사용하지 않는다.

첫 관리자 생성은 단일 트랜잭션으로 처리한다. 성공하면 설정 키 DB 레코드와 파일을 폐기하고 추가 초기 설정을 거부한다. 공개 회원가입은 제공하지 않는다. 계정이 없어도 인증은 기본 활성화된다. Python의 `create_app(auth_required=False)`는 명시적 테스트 fixture용으로만 사용한다. 이 경우에도 토큰이 설정되어 있거나 계정이 생성되면 인증을 강제한다.

## 권한과 세션

| 역할 | 권한 |
| --- | --- |
| 관리자 | 공유 워크스페이스, 계정/접속 기록, 서버 연결/실행 프로필/데이터 위치, SDK 토큰, 수동 통합 동기화 |
| 사용자 | 공유 프로젝트·학습·데이터·평가·예약·파이프라인·레지스트리 운영, 본인 비밀번호 변경 |

사용자별 프로젝트 격리는 제공하지 않는다. 일반 사용자도 공유 학습을 실행/중단할 수 있다. 서버 연결 설정, 계정 관리, SDK 토큰 관리는 API에서 관리자 권한을 확인한다. 마지막 활성 관리자는 비활성화하거나 일반 사용자로 바꿀 수 없다.

- 비밀번호: 10~128자, Argon2id. 평문을 DB/로그에 기록하지 않는다. [argon2-cffi 공식 문서](https://argon2-cffi.readthedocs.io/en/stable/).
- 세션: 무작위 256비트 이상, DB에는 SHA-256만 저장, 절대 유효기간 12시간, 사용자당 최대 10개. 서버 재시작 후에도 유효하다.
- 쿠키: HttpOnly, SameSite=Strict, 운영 HTTPS에서 Secure. 비밀번호 변경/초기화·역할/상태 변경 시 모든 기존 세션을 폐기한다. 본인 비밀번호 변경은 현재 브라우저에 새 세션을 발급한다.
- 관리자 생성/초기화 임시 비밀번호는 첫 사용 때 강제 변경한다. 그 전에는 계정 확인·비밀번호 변경·로그아웃만 가능하다.
- 로그인/초기설정/비밀번호 확인 시 DB에 지속되는 15분 창 제한: 계정 키당 10회, 직접 연결 IP당 30회. 프록시의 X-Forwarded-For를 임의 신뢰하지 않는다. SSH/프록시 뒤의 사용자는 IP 한도를 공유할 수 있다.
- 상태 변경 요청은 JSON과 X-Geppetto-Request 헤더 및 동일 Origin을 요구한다.
- Users 화면은 최근 100개 계정 활동을 표시한다. 비밀번호·세션 원문은 활동에 포함하지 않는다.

## 비밀번호 분실 복구

다른 관리자가 Users에서 초기화할 수 있다. 모든 관리자가 비밀번호를 잊은 경우 서버 접근 권한으로 다음 명령을 사용한다. 새 비밀번호는 대화형 입력이며 명령 인수나 셸 히스토리에 기록되지 않는다.

```bash
kubectl --context=mlops -n geppetto-system exec -it deployment/geppetto -c app -- \
  python -m geppetto.auth --home /state --username admin
```

복구는 해당 계정을 활성화하고 모든 세션을 폐기한다. 다음 로그인 때 다시 비밀번호를 변경한다.

## 검증

`tests/test_auth.py`: 초기설정 경합, 기본 인증, 토큰 웹 로그인/과거 쿠키 거부, CSRF/Secure 쿠키, 세션 영속성/만료/폐기, 계정 잠금, 관리자 API 경계, 마지막 관리자 보호, 비밀번호 초기화.

`tools/browser_accounts.py`: 실제 브라우저로 초기 설정 → 사용자 추가 → 로그인/로그아웃 → 강제 비밀번호 변경 → 본인 비밀번호 변경 → 관리자 비활성화. 데스크톱과 모바일 화면 확인.

# 특정 GPU 지정: 후보 및 격리 실증 계획

상태: **미실증**. 이번 구현은 Pod/컨테이너 생성, GPU 사용, 클러스터 조회·변경을 하지 않았다.
운영 현황은 인계 문서의 2026-09-26 관측값이며 이번에 재확인한 값이 아니다.

후보는 NVIDIA DRA v0.5.0이다. 기존 개수 기반 device plugin을 유지하는 한 특정 UUID
요청은 제품 기능으로 제공하지 않는다. 환경변수로 할당을 우회하지 않는다.
[공식 전제조건](https://dra-driver-nvidia-gpu.sigs.k8s.io/docs/prerequisites/)을
2026-09-26 확인했다. GPU 할당은 Kubernetes 1.34.2 이상, CDI 런타임 및
Container Toolkit 1.18 이상을 요구한다. 인계 문서의 Kubernetes 1.34.0은 조건 미충족이다.
운영 채택 시 Kubernetes/런타임/할당 계층 변경 검토가 필요하며 현재 승인 범위에 없다.

[공식 GPU 선택 가이드](https://dra-driver-nvidia-gpu.sigs.k8s.io/docs/guides/gpu-allocation/allocating-gpus/)의
ResourceSlice와 CEL 기반 선택을 검증 후보로 삼는다. 실제 버전에서 공개하는 장치 식별
속성과 물리 UUID의 대응을 확인한 뒤 선택식을 고정해야 한다. 문서만으로 UUID 실증을
통과했다고 판단하지 않으며, 검증되지 않은 배포 YAML은 제공하지 않는다.

## 격리 방식 결정

우선 방식은 **별도 물리 GPU 호스트의 테스트 클러스터**다. 운영과 GPU 장치를 공유하지 않는다.
동일 호스트의 별도 namespace/minikube profile은 물리 GPU 격리가 아니므로 불충분하다.
별도 호스트가 없다면 실증은 보류한다. 운영 GPU를 분리하는 방식은 기존 할당기에서의 제외,
호스트 직접 사용 차단, 진행 작업 영향 검토와 별도 운영 전환 승인이 선행해야 한다.
단순 idle 상태는 독점 할당 증거가 아니다.

## 승인 후 실증 절차

1. 테스트 호스트/클러스터 ID, 버전·CDI·드라이버·DRA 이미지 digest, 할당기 독점 소유,
   GPU UUID 목록을 기록한다. 운영 호스트와 다름을 확인하고 다른 호스트 작업도 확인한다.
2. ResourceSlice 장치와 물리 UUID를 대응시킨 뒤 UUID A 요청 작업을 실행한다.
   요청, ResourceClaim 실제 할당, 컨테이너 내부 `nvidia-smi` 결과를 동일 실행에 보존한다.
3. A를 보유한 동안 두 번째 A 요청이 Pending인지 확인한다. 임의 B 전환은 실패다.
4. 정상 종료/실패/사용자 중단을 각각 실행하고 Claim 반환 및 후속 A 작업 성공을 확인한다.
5. 동일 DRA 할당기를 사용하는 자동 배정 작업과 지정 작업을 함께 검증한다.
   서로 다른 할당기를 같은 물리 장치에 중복 적용하는 테스트는 하지 않는다.
6. 운영 영향 없음, 중복 사용 없음, 작업/Claim 정리를 확인하고 증거·관측 시각을 저장한다.

검증 기록 필수 열: 시나리오, 요청 UUID, 실제 UUID, claim/pod UID, 시작/종료 시각,
대기 관측, 반환 관측, 종료 원인, 증거 파일, 결과. 다섯 통과 기준(일치/배타/반환/자동배정
충돌 없음/운영 무영향)을 모두 만족해야 기능을 활성화한다. mock 테스트는 실증을 대체하지 않는다.

예약 정책 초안: GPU 부족 시 대기, 다른 UUID로 대체 금지, 선점 금지, 반복 실행 중복 시 skip.
동시 실행 상한·재시도·누락 예약 정책은 단계 2 계약에서 고정한다.

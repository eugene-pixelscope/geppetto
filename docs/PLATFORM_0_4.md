# 제페토 0.4 — 작업 연결, 복구, GPU 배분과 노드 관측

Airflow·Volcano를 설치하지 않고 제페토의 기존 Kubernetes Agent 실행 경로를 확장한다.
MLflow는 실험·체크포인트·모델 버전 및 별칭에 사용한다. 추론 API 배포는 포함하지 않는다.

## 화면에서 사용

- 노드 → **자원 사용량**: CPU, 메모리, GPU별 사용률/메모리/온도/전력,
  디스크, 네트워크 수신·송신, 최근 최대 240회 추이, 실행·대기 작업.
  Home에도 CPU·메모리·GPU 사용률을 요약한다. 측정이 없으면 `미측정`,
  60초가 지나면 갱신 지연으로 표시한다. GPU 예약량은 사용률과 별도로 표시한다.
- Manage → **파이프라인**: 기준 학습을 선택해 학습 → best.pt 평가 → 품질 기준에 따른
  MLflow 별칭 지정까지 폼으로 구성한다. 고급 JSON에서는 분기·합류, 다른 노드,
  `type: train/evaluate/register`, `input_from`, `gate`, 단계별 `retry`를 지정한다.
  입력 체크포인트는 선행 단계 성공 후 URI와 SHA-256을 확정하고 실행 시 재검증한다.
  `train`의 input_from은 가중치 초기화이며 optimizer 상태 재개와 구분한다.
- 실패 실행 → **실패한 단계 다시 실행**: 같은 고정 설정으로 새 run/Job/출력 경로를 생성한다.
  성공한 선행 실행은 유지하며 건너뛴 하위 단계만 새 실행으로 만든다.
  이전 시도와 재시도 링크를 보존하고 같은 요청을 반복해도 중복 시도를 만들지 않는다.
- 학습 생성 → **인프라 장애 자동 재시도 횟수**: 기본 0회, 최대 10회.
  기본 대상은 Agent가 관측한 Evicted/NodeLost/Shutdown이다. 일반 학습 실패는
  고급 정책 `on: any_failure`를 선택해야 자동 재시도한다.
  자원 반환 확인 후 `delay_seconds × backoff^attempt`를 적용하며 최대 지연은 하루다.
  재시도 대기 중에는 취소할 수 있다. 재시도는 처음부터 실행하며 체크포인트 재개와 다르다.
- 예약 → **누락된 예약 보충 실행**: UTC 오프셋을 가진 과거 구간을 검토한 뒤 빠진
  cron occurrence만 생성한다. 예약 시간대를 적용하고 logical_date를 기록한다.
  최대 366일·500회, 이미 존재하는 실행은 제외한다. 반복 호출과 재시작에 멱등이다.
  기존 예약의 다음 시각과 활성 상태를 바꾸지 않는다. 실패한 기존 실행은 재시도 기능으로 복구한다.
- Manage → **GPU 배분**: 프로젝트별 GPU 최대량, 우선 보장량, 가중치, 동시 작업 수.
  대기 작업에 우선 보장량을 먼저 적용하고 작업 우선순위·가중치·생성 순서로 배정한다.
  보장량은 가용 자원이 생길 때의 우선권이며 물리 GPU의 별도 예약이나 시작 시각 보장이 아니다.
  노드 용량과 최근 관측한 외부 Pod 예약량도 함께 고려한다.
- 학습 생성 → 노드당 **GPU 개수**, **추가 노드**, **우선순위**, **자원 양도 허용**.
  양도 허용 공 학습은 epoch 체크포인트를 MLflow에 게시한다. 더 높은 우선순위 프로젝트가
  선점을 허용하고 피해 작업의 프로젝트 보장량을 침해하지 않을 때만 중단한다.
  반환 확인 후 게시된 상태에서 새 실행으로 자동 재개한다. 게시된 체크포인트가 없으면 선점하지 않는다.

## 다중 GPU와 노드 실행 계약

공 모델 어댑터에 torchrun 실행을 추가했다. 노드 실행 설정의 `max_gpus`를 명시적으로 설정하고
새 러너를 포함한 immutable 이미지 digest를 연결해야 한다. 기존 이미지 설정의 기본값은 1이다.
글로벌 batch는 전체 GPU 수의 배수여야 한다. 등번호 어댑터는 단일 GPU 계약을 유지한다.

한 노드의 여러 GPU는 하나의 Pod에서 함께 요청한다. 다중 노드는 다음 조건이 필요하다.

- 같은 Kubernetes 클러스터·namespace·이미지 digest·MLflow URI.
- 동일 데이터 위치, 동일 데이터 PVC와 ReadWriteMany 결과 PVC.
- 각 노드 실행 프로필의 `shared_storage: true`, 충분한 GPU 용량.
- Agent의 Service get/create 권한과 노드 사이 rendezvous/NCCL 통신.

중앙 트랜잭션에서 모든 노드의 할당량을 함께 확보하고, 노드별 결정적 Job과
소유자 UID를 가진 rendezvous Service를 생성한다. 하나의 노드가 실패하면 전체 구성원을
UID 조건으로 종료하고 반환을 확인한다. rendezvous는 300초, 스케줄링 대기는 600초 후 정리한다.
이는 제페토 내부의 일괄 예약이다. 다른 스케줄러와 Kubernetes 전역에서 원자적으로
자원을 확보하는 Volcano PodGroup 수준의 gang scheduling은 아니다.

모든 rank에 제페토 콜백을 설치하고 global rank 0만 기록·체크포인트를 게시한다.
재개에는 기존 GPU 토폴로지와 rank별 RNG 상태를 요구한다. epoch 경계 상태를 복원하며
DataLoader prefetch와 분산 커널까지 비트 단위 동일성을 보장하지 않는다.

## 관측 설치

- 호스트의 로컬 작업 공간: `GEPPETTO_LOCAL_METRICS=1`.
  `tools/serve_local_catalog.sh`에서 활성화한다. `/proc`, `statvfs`, `nvidia-smi`를 읽는다.
- 원격 Agent: Metrics Server가 있으면 CPU·메모리를 읽는다.
  `deploy/node-metrics.yaml`은 GPU·디스크·네트워크용 읽기 전용 DaemonSet과 조회 RBAC다.
  수집기 이미지를 해당 클러스터에서 접근할 수 있도록 빌드/배포해야 한다.
  NVIDIA runtime의 utility 라이브러리 주입이 필요하다. GPU를 예약하거나 학습을 실행하지 않는다.
- GPU별 정보는 장치 전체 사용량이다. 특정 학습 프로세스에 대한 사용량으로 오인하지 않는다.
  메모리 정의는 source에 따라 host MemTotal−MemAvailable 또는 Metrics Server working set이다.
  디스크는 수집기 호스트 루트 파일시스템, 네트워크는 노드 인터페이스 합계다.

## 검증과 적용 경계

새 Python 통합 테스트는 결과 전달/부분 재실행/재시도 한도/예약 멱등성/자원 정책/
다중 노드 예약·실패 정리·재시작/torchrun 런처/측정 갱신 지연을 검사한다.
`tools/browser_orchestration.py`는 격리 카탈로그에서 폼 제출과 320/375/768/1440px를 검사한다.

2026-09-29 현재 호스트의 A100 8개 모두 기존 학습에 사용 중이어서, 이번 변경의
실제 다중 GPU·다중 노드 학습/재개 검증은 수행하지 않았다. 운영 학습을 중단하거나
공유 GPU에 검증 작업을 추가하지 않는다. 이 검증 전에는 운영 프로필의 max_gpus를 올리지 않는다.
